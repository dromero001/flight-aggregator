# Increments

One row per increment, to make each increment visible: the plan or delivery group, its tag, its first and closing commit on `main`, its tasks, its review verdicts and the CI run of its closing commit.

**How work reached `main`.** Plans 0 to 4 ran on `main` itself, without task branches ([plan 4's rulings](progress/2026-11-15.md#the-controllers-rulings)). From plan 5 on, each task was built on its own branch and git worktree, reviewed by subagents acting as the reviewers defined in [`.claude/agents/`](../../.claude/agents), rebased when `main` had moved, and integrated into `main` by fast-forward once approved and green, so the history is linear, with no pull requests or merge commits. CI runs on every push to `main` (from plan 1, Task 5). Since 2026-11-15, 16:50, each task branch is pushed to GitHub as `wip/…` after every commit, and those branches are kept as each task's record; a branch rebased before integration holds the commits as reviewed, so their hashes can differ from `main`'s. G3 and G4a, built after `v1.0.0`, are integrated through pull requests.

**Columns.** *First* is the first commit of the increment's first task; *closing* is the commit that records the final approval of its end-of-plan review, or that closes the plan when tasks followed that review. Plans overlap in time from plan 3 on, so the commits between first and closing are not all the increment's own; a commit count is given only where the range is contiguous. Fixes of a plan's last Minors that reached `main` after its closing commit are in its progress report. "Not recorded" means the repository holds no record of that fact.
