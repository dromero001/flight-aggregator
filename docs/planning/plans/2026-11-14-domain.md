# Domain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Every production change follows `superpowers:test-driven-development` and `CLAUDE.md`. Reviews follow the review protocol in `CLAUDE.md`: `functional-reviewer` and `code-reviewer` after every task, plus `risk-reviewer` on the whole plan at the end.

**Goal:** The domain module turns the legs that providers sell into every sellable itinerary of up to two stops, with its identity and its final price, in pure Java.

**Architecture:** One flat package, `com.flightaggregator.domain`, of immutable records and stateless rule classes. Value types (`Airport`, `Carrier`, `ProviderId`, `Money`) validate themselves; `Leg` is one provider's offer of a flight and `LegKey` the flight's identity; `LegDeduplicator`, `ConnectionRules` and `PricingPolicy` hold the rules of §4; `Itinerary` refuses to exist unless its legs connect; `ItineraryBuilder` enumerates every valid itinerary. The current time is passed in as an `Instant`, because the clock is an outbound port of the application layer (§6).

**Tech Stack:** Java 25 and the JDK only (ArchUnit rule 1); JUnit 6.1.3 and AssertJ 3.27.7, already provided by the convention plugin. No new dependency.

**Spec:** [design spec](../design-spec.md) — §2 (goals, non-goals), §4 (domain rules, including the four decisions taken before this plan), §4.2 (instants and offsets), §5.3 (materialised itineraries), §5.4 (sort keys), §6 (modules and ports), §6.3 (freshness, re-price), §6.5 (kept legs), §6.7 (malformed records), §8 (unit tests). Roadmap: [plan 2](../roadmap.md).

## Global Constraints

- Package `com.flightaggregator.domain`; main code in `domain/src/main/java/com/flightaggregator/domain/`, tests in `domain/src/test/java/com/flightaggregator/domain/`. Only `java.*` imports in main code: no framework, persistence or provider type (§2 anti-goals, §6).
- No `Instant.now()`, `Clock` or randomness in the domain: every time-dependent rule takes `Instant now` as a parameter.
- Connection rules, verbatim from §4: arrival airport equals the next departure airport; connection time **≥ 45 min and ≤ 24 h**, both bounds inclusive, measured between instants; **1 to 3 legs**; no airport visited twice; no leg already departed (departure **at or before** `now` counts as departed).
- Leg deduplication (§4): same airline, flight number, origin, destination and departure instant → the cheapest offer wins.
- Price (§4): the sum of the leg prices, then **+5%**, in **EUR**, rounded to cents **once, half-up**. Other currencies are a non-goal (§2): `Money` has no currency field.
- Itinerary identity (§4): a name-based UUID of the itinerary's leg keys; price, provider and quote time are not part of it.
- Freshness (§4): every leg carries `quotedAt`; an itinerary's `quotedAt` is the oldest of its legs'.
- Carrier filter (§4): an itinerary belongs to a carrier only when every leg is operated by it; interlining (mixed carriers and providers) is valid.
- Gates: `./gradlew build` green before every commit, with Spotless (google-java-format) and the JaCoCo gate (90% lines, 80% branches) inside it.
- TDD one test at a time; the red → green evidence of each test goes in the run's progress report (`docs/planning/progress/<date of the run>.md`, section "Domain run (plan 2)").
- Scope (`brief-scope`): only what this plan lists. An extra discovered mid-task goes to the progress report under "Extras for the user to decide" and is not built.
- English everywhere; no AI attribution in commits; push only after `gh api user --jq .login` prints `dromero001` (`CLAUDE.md`).

## Decisions this plan takes (left to the builder by §11; for the user's review)

| Decision | Why |
|---|---|
| One flat `domain` package | About twelve types that all speak about legs and itineraries; sub-packages would add `public` modifiers and nothing else |
| `Leg` is one provider's offer; `LegKey` is the flight | §4 dedup compares offers of the same flight, and re-price needs the provider of the winning offer (§6.3) |
| `ProviderId` is an opaque string, not an enum | §6.7: a fourth provider means one adapter and no domain change |
| `Money` stores a `BigDecimal` at scale 2, is never negative, and **rejects** more than two decimals instead of rounding them | Provider prices have cents (§6.7); a third decimal is a malformed record, not something to round silently (§2 anti-goals) |
| Flight number 1–9999; carrier designator two characters `[A-Z0-9]` (e.g. `U2`) | IATA formats |
| Equal-price duplicates: the lowest `ProviderId` wins | Deterministic, so re-price quotes the same provider on every run |
| Itinerary id: `UUID.nameUUIDFromBytes` over the canonical leg keys joined by `\|` | The JDK's name-based UUID; MD5 here is an identity hash, not a security control |
| `ItineraryBuilder` returns a lazy `Stream<Itinerary>` | ~1M itineraries (§4.1): the ingestion can write them in batches without holding all of them in memory |
| The rule classes are stateless `final` classes with static methods | Their values are fixed by the spec; there is nothing to configure or inject |

## Out of scope (carried to later plans)

- The airport catalogue, its outbound port and discarding legs with an unknown airport (§4, "Unknown airports"): plan 4. This plan only validates the IATA format.
- The per-origin rebuild for the stale-route refresh (§4.1): plan 4, designed with its caller.
- Parsing provider payloads into `Leg` (§6.7): plan 4. Re-price (§6.3): plan 5.
- Cross-checking the builder's count on the real mock dataset against the calibration estimate (~1M): plan 4's ingestion test, because `domain` cannot depend on `mock-gds`.
- Checking ArchUnit rules 2–4 without `allowEmptyShould`: plan 4, when the first application and adapter classes land.

## Review Focus

1. **Times in different offsets, and a DST change during a layover:** every comparison must use instants, never local times (§4.2). Pinned by Task 2 `acceptsAnArrivalWithAnEarlierLocalTime` and Task 3 `rejectsAConnectionThatLooksLongEnoughInLocalTime` / `acceptsAConnectionThatLooksTooShortInLocalTime`.
2. **Two providers selling the same leg at the same price:** the winner must not depend on the input order, or re-price would flip between providers. Pinned by Task 2 `breaksPriceTiesByProviderId`.
3. **A leg departing exactly now, and a departed first leg whose connection is still in the future:** neither is sold, but the connection is still offered on its own. Pinned by Task 3 `sellsOnlyLegsDepartingAfterNow` and Task 5 `skipsDepartedLegs`.
4. **Circular trips** (MAD→LHR→MAD, MAD→LHR→CDG→LHR) pass every connection rule but must be rejected. Pinned by Task 4 `rejectsVisitingAnAirportTwice` and Task 5 `rejectsReturningToTheOrigin` / `rejectsRevisitingAStop`.
5. **A re-quote changes price, provider and quote time, but not the flights:** the itinerary keeps its id, so a cursor or a re-price request still points at it. Pinned by Task 4 `keepsItsIdWhenRequoted`.

- [ ] **Step 2: Implement `ItineraryBuilder.build`.** The tests do not pin the algorithm, and the combinatorics must stay bounded at ~1M itineraries (§5.3):
